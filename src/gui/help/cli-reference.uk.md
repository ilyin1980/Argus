# Командний рядок і автоматизація

Пакет містить **два виконуваних файли, зібрані з однієї бібліотеки-ядра**:

| | |
|---|---|
| `imageworker-gui` | вікно, у якому ви це читаєте |
| `imageworker` | консольний; усе те саме, плюс опції індексації, яких немає в ГУІ |

Вони поділяють усю логіку, тож папку, проіндексовану одним, читає інший. Жоден
не є обгорткою над іншим — обидва лінкуються з тим самим статичним ядром.

---

## Контракт виводу

На це можна покладатися у скриптах; він навмисно стабільний.

- `--json` пише **JSON із роздільником-рядком у stdout**, по одному об'єкту в
  рядку. Кожен результат несе і `rel` (відносно проіндексованої папки), і
  `path` (абсолютний).
- `--paths` пише **самі абсолютні шляхи**, по одному в рядку, для конвеєра. У
  `dupes` групи розділені порожнім рядком. Опція вмикає `--quiet`, а поєднання
  з `--json` є помилкою, а не мовчазним вибором однієї з них.
- Прогрес, попередження й помилки завжди йдуть у **stderr**, ніколи у stdout.
- Результати виходять у детермінованому порядку.
- Коди виходу: **0** — щось знайдено, **1** — нічого не знайдено, **2** —
  помилка.

## Команди

```
imageworker index  <dir> [--features] [--jobs N] [--ext png,jpg] [--force]
imageworker vocab  <dir> [--words 2048] [--sample 120000]
imageworker find   <dir> --image shot.png [--roi x,y,w,h] [--shortlist N] [--top N]
imageworker dupes  <dir> [--distance 4] [--exact-only] [--near-only]
imageworker query  <dir> --image ref.png [--top 20]
imageworker match  --query q.png --asset a.png
imageworker stats  <dir>
imageworker doctor [--extract img.png]
imageworker formats
```

Кожна команда приймає `--db <path>`, щоб покласти індекс не в
`<dir>/.imageworker`, а деінде.

### Підготувати папку до пошуку об'єктів

```
imageworker index D:/game/Assets --db D:/indexes/game/index.db --features
imageworker vocab D:/game/Assets --db D:/indexes/game/index.db
```

Сам по собі `index` дає пошук дублікатів. `--features` додає нейронні
дескриптори, а `vocab` тренує на них індекс шортліста; для роботи `find`
потрібні обидва кроки. Перезапускайте `vocab` після додавання великої партії
асетів, а не після кожного файлу.

### Пошук

```
imageworker find D:/game/Assets --db D:/indexes/game/index.db --image shot.png --json
```

Передавайте `--roi x,y,w,h`, коли знаєте, де об'єкт. Це найдієвіша опція: на
обведеній ділянці пошук приблизно вп'ятеро швидший і знаходить приблизно вдвічі
більше збіжних точок.

### Інші гілки git

```
imageworker index D:/game/Assets --branches all
imageworker index D:/game/Assets --branches release/1.4,feature/new-ui
```

Картинки читаються зі сховища об'єктів, тож нічого не викачується, а робоче
дерево лишається недоторканим. Названий набір є повним: гілка, проіндексована
раніше й не названа знову, вилучається з індексу. `--branches all` бере всі
локальні гілки, а `--remote-branches` додає віддалені.

Повторна індексація дешева. Гілка, вершина якої не зрушила, пропускається без
читання дерева, а всередині гілки зміни визначає ідентифікатор blob — адреса за
вмістом, тобто надійніша перевірка, ніж розмір і час зміни для файлів.

Рядки з гілки ніколи не показують шлях у файловій системі, бо такого файлу
немає. Звичайний вивід і `--paths` друкують власний синтаксис git `гілка:шлях`,
який приймає `git show`; `--json` замість `path` несе `ref`, `blob` і `rev`.

Під Git LFS об'єкти беруться з локального сховища LFS. Відсутні об'єкти
підраховуються й повідомляються один раз, із порадою `git lfs fetch --all`;
нічого не завантажується самочинно.

### Конвеєр

```
imageworker dupes D:/game/Assets --paths > groups.txt
imageworker find  D:/game/Assets --image shot.png --paths | clip
```

## Перевірка встановлення

```
imageworker doctor
```

Повідомляє версії ONNX Runtime та OpenCV, доступні провайдери виконання і чи
справді вдається створити сесію DirectML на цьому драйвері — а це не те саме,
що просто наявність провайдера у списку. `--extract <image>` проганяє
екстрактор по одному файлу й повідомляє, скільки ключових точок знайдено і
скільки це тривало.

## Де що лежить

```
<папка індексу>/
  index.db              SQLite: файли, хеші, прев'ю, зсуви дескрипторів
  features/desc.f16     дескриптори, половинна точність
  features/kpts.f32     ключові точки
  features/vocab.bin    візуальний словник
  features/bow.bin      індекс шортліста
```

Видалення папки індексу скидає все й не зачіпає нічого іншого. Шляхи в базі
зберігаються **відносно проіндексованої папки**, тож індекс лишається чинним,
коли те саме сховище змонтоване в іншому місці.

Моделі шукаються в `models/` поруч із виконуваним файлом, а потім у
батьківських папках над ним — тож і зібраний пакет, і дерево збірки працюють
без налаштування.

## Збірка

```
cmake --preset msvc-release -DIMAGEWORKER_WITH_INFERENCE=ON
cmake --build --preset msvc-release
cmake --install build/msvc-release
```

`IMAGEWORKER_WITH_INFERENCE=OFF` збирає без ONNX Runtime та OpenCV; пошук
дублікатів працює, пошук об'єктів — ні.

Крок install збирає самодостатню папку: усі залежності поруч із виконуваними
файлами, нічого не береться з `PATH`. Збірка в один файл неможлива: ONNX
Runtime із DirectML постачається лише як DLL, а `DirectML.dll` — це
розповсюджуваний компонент, який узагалі не можна злінкувати всередину.
